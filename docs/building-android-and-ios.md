# Building for Android and iOS

The app is one Expo project that targets both platforms. The Android build is
checked in under `mobile/android/`, and the iOS project is generated by
Expo prebuild, which only runs on macOS or Linux.

## Android

### Local build (Windows, macOS or Linux)

```bash
cd mobile
npx expo prebuild --platform android --clean   # only after changing app.json
cd android
./gradlew assembleRelease                      # macOS/Linux
gradlew.bat assembleRelease                    # Windows
```

The APK lands in:

```
mobile/android/app/build/outputs/apk/release/app-release.apk
```

### Signed release APK

The release build is signed with a local keystore, kept out of git under
`mobile/android-keys/`. The `withReleaseSigning` config plugin copies the
keystore into the generated project and injects the credentials, so the
build is reproducible.

For a build on another machine, export the four values first:

```bash
export MIGRAINKE_STORE_FILE=migraine-beta.keystore
export MIGRAINKE_STORE_PASS=...
export MIGRAINKE_KEY_ALIAS=...
export MIGRAINKE_KEY_PASS=...
```

### EAS cloud build

```bash
cd mobile
npx eas-cli build --platform android --profile preview
```

The `preview` profile produces an APK for internal distribution and the
`production` profile produces an AAB for the Play Store. Both bake in
`EXPO_PUBLIC_API_URL`, so the app points at the public backend.

## iOS

### What is needed

- macOS with Xcode
- An Apple Developer account, for a device build
- CocoaPods (`pod install`)

`npx expo prebuild --platform ios` refuses to run on Windows, because the
iOS native project is generated from macOS-only templates. The repository
therefore does not contain an `ios/` folder.

### Producing an .ipa from Windows with EAS

The iOS binary is compiled on EAS's own macOS machines, so the whole
process runs from Windows. A free Expo account is enough to build; an Apple
Developer account is needed for the result to install on a real iPhone.

**One command:**

```powershell
cd mobile
powershell -ExecutionPolicy Bypass -File scripts\build-ios-ipa.ps1
```

The script checks the Expo session, validates the project, starts the
build and prints the link to the finished `.ipa`. If you are not signed in
yet it tells you what to do:

```bash
# 1. Create a free account at https://expo.dev/signup
# 2. Sign in (opens a browser)
npx eas-cli login

# 3. Build
npx eas-cli build --platform ios --profile preview
```

The build takes roughly 10-20 minutes. EAS prints a link when it is done,
and the `.ipa` can be downloaded from there.

**Build profiles** (in `mobile/eas.json`):

| Profile | Result |
|---|---|
| `preview` | Internal distribution, an `.ipa` for direct install. The default choice. |
| `development` | A development client with a simulator build. |
| `production` | An App Store build (`.ipa` for TestFlight, `.aab` for the store). |

**Simulator build**, which needs no Apple account but only runs on a Mac:

```bash
npx eas-cli build --platform ios --profile preview --target simulator
```

**Listing and downloading finished builds:**

```bash
npx eas-cli build:list --platform ios
npx eas-cli build:view <build-id>
```

### Signing

The first iOS build asks which Apple team to sign with. Set it up once:

```bash
npx eas-cli credentials
```

Without an Apple Developer account EAS can still build, but the result is
a simulator build that will not install on a physical iPhone. A paid
account is required for a build that real devices accept.

### Local build on a Mac

```bash
cd mobile
npx expo prebuild --platform ios --clean
cd ios
pod install
open MigraineDetectorBeta.xcworkspace   # workspace, not the project
```

Then select the `MigraineDetectorBeta` scheme and run, or build an archive
for distribution.

### What differs on iOS

- **The bonded-devices list is Android only.** The native module that reads
  the system's paired-device list calls `BluetoothAdapter.getBondedDevices()`,
  which has no iOS equivalent. On iOS the app shows the nearby scan only, and
  a paired watch appears in the scan when it is in range and advertising.
- **The simulator has no Bluetooth radio.** The Connect Wearable screen
  needs a physical device.
- **Permissions are requested at runtime** rather than through the manifest,
  and iOS shows the system prompt the first time the app scans.
- **Background scanning is off by default.** The app only scans while the
  Connect Wearable screen is open, which matches the way the screen reads.
- **The launch screen** uses the brand icon on the brand background, set by
  the `expo-splash-screen` config plugin.
